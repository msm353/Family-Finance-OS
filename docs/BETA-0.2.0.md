# آماده‌سازی استفادهٔ آزمایشی 0.2.0-beta

**وضعیت:** نسخهٔ آزمایشی با تگ `v0.2.0-beta` منتشر شده است؛ آزمون گوشی نسخهٔ جدید هنوز ثبت نشده است.

بستهٔ نسخه: `0.2.0-beta`، Android `versionCode=5`، شناسهٔ ثابت `io.github.msm353.ffos`، Dexie نسخهٔ ۲. ساخت کنترل امضا artifact تولید می‌کند؛ به‌تنهایی Release ایجاد نمی‌کند.

## شواهد فعلی

- ۵۰ آزمون Node، شامل Dexie واقعی روی fake-indexeddb در حافظه، موفق‌اند. این آزمون‌ها پایگاه مرورگر یا گوشی کاربر را تغییر نمی‌دهند.
- مهاجرت تاریخ‌های فارسی/عربی، حفظ مقدار خام و شناسه، توقف دادهٔ ناسازگار، اصلاح صریح، اجرای دوباره، تغییر منبع پس از پیش‌نمایش و ارتقای مسدودشده پوشش داده شده‌اند.
- خطا پس از نوشتن جدول یا تاریخچه و خطا پیش از ثبت metadata، کل نوشتن را برمی‌گرداند. ویرایش هم‌زمان با revision قدیمی رد می‌شود.
- هزینه، درآمد و انتقال؛ ویرایش، حذف، بازگردانی، تاریخ آغاز و آینده؛ محدودهٔ امن مبلغ و جمع؛ بازیابی کامل نسخهٔ ۱ و ۲ آزمون دارند.
- رندر ایستای بخش حساب‌ها و فرم هزینه نیز آزمون شده است؛ این آزمون تعامل مرورگر را اثبات نمی‌کند. آزمون رابط مرورگر نامزد جدید باز است: بازکردن `127.0.0.1:4190` دو بار با پایان مهلت بررسی خودکار دسترسی ابزار متوقف شد. این نتیجه خطای برنامه یا آزمون موفق UI نیست.
- ساخت وب و فایل‌های آفلاین موفق‌اند؛ Vite هشدار حجم chunk اصلی حدود ۵۶۰ کیلوبایت (فشرده حدود ۱۷۰ کیلوبایت) دارد. آزمون کارایی گوشی و فایل‌های نزدیک سقف ۱۰ مگابایت باز است.
- سه هشدار audit متوسط مربوط به مسیر توسعهٔ `@capacitor/cli → xcode → uuid` باقی است؛ downgrade یا `audit fix --force` انجام نشده است.
- کارکرد آفلاین و خروجی JSON نسخهٔ قبلی طبق گزارش کاربر قبول شده‌اند؛ این شواهد جای آزمون APK جدید و پشتیبان نسخهٔ ۲ را نمی‌گیرند.

## آزمون گوشی پیش از شروع روزمره

۱. JSON نسخهٔ فعلی را خارج از برنامه نگه دارید؛ APK شمارهٔ ۵ را روی شمارهٔ ۴ نصب کنید. هزینه‌های قبلی باید باقی بمانند، با تاریخ درست و بدون تکرار.
۲. حساب A با ماندهٔ ۱٬۰۰۰٬۰۰۰ تومان و حساب B با صفر در ابتدای امروز بسازید. هزینهٔ ۱۰۰٬۰۰۰، درآمد ۲۰۰٬۰۰۰ و انتقال ۳۰۰٬۰۰۰ از A به B ثبت کنید. A باید ۸۰۰٬۰۰۰ و B باید ۳۰۰٬۰۰۰ شود. انتقال نباید وارد گزارش هزینه شود.
۳. انتقال را به ۲۵۰٬۰۰۰ ویرایش کنید: A برابر ۸۵۰٬۰۰۰ و B برابر ۲۵۰٬۰۰۰. حذف آن: A برابر ۱٬۱۰۰٬۰۰۰ و B صفر. بازگردانی: دوباره ۸۵۰٬۰۰۰ و ۲۵۰٬۰۰۰. پیش از تأیید حذف، لغو را هم بررسی کنید.
۴. برنامه را ببندید و بدون اینترنت باز کنید. موجودی‌ها و تراکنش‌ها باید باقی بمانند.
۵. پشتیبان کامل نسخهٔ ۲ بسازید و وجود فایل را خارج از برنامه بررسی کنید. آن را انتخاب کنید، بازیابی را لغو کنید و ماندن داده‌ها را ببینید. سپس بازیابی تأییدشده را با همان دادهٔ آزمایشی بررسی کنید: شناسه‌ها، تاریخچه و حذف‌شده‌ها باید حفظ شوند.
۶. لغو اشتراک فایل و بازیابی JSON قدیمی را فقط با دادهٔ آزمایشی بررسی کنید؛ بازیابی فایل قدیمی تمام حساب‌ها و تراکنش‌های فعلی را جایگزین می‌کند.

قبولی این موارد با گزارش کاربر ثبت می‌شود. برای آزمون نصب تازه، از نمونهٔ جدا/گوشی دوم استفاده شود؛ برای آزمون، برنامهٔ حاوی دادهٔ روزمره حذف نشود.

## چرخهٔ استفاده و نسخه‌های بعد

پس از قبولی آزمون گوشی، از حساب‌هایی با ماندهٔ آغازین روشن شروع کنید؛ تاریخ پیش از ماندهٔ آغازین پذیرفته نمی‌شود. هزینهٔ قدیمی بدون حساب همچنان در گزارش هزینه قرار دارد و روی موجودی حساب اثر ندارد.

از بخش پشتیبان JSON کامل بگیرید، مخصوصاً پیش از هر ارتقا یا بازیابی. CSV فقط خروجی هزینه است. گزارش خطا شامل نسخه، مسیر صفحه، مراحل تکرار، نتیجهٔ مورد انتظار و نتیجهٔ دیده‌شده باشد؛ ارسال کل دادهٔ مالی لازم نیست.

در نسخهٔ بعد ابتدا اشکال‌های حفظ داده، مانده و ثبت روزمره برطرف شوند؛ سپس ادامهٔ فاز ۲ و فازهای بعد طبق Roadmap انجام شود. هر APK شمارهٔ ساخت بزرگ‌تر و همان کلید امضا دارد.
